GlamChain Widget — Distribution Demo (v3, with live-mode bridge)

One widget file. Two modes. Demo mode = mock WhatsApp animation, no backend. Live mode = real booking persistence via /api/public/booking with conflict detection, rate limiting, and customer auto-upsert. Set business.bookingApiUrl + business.locationId in the config to go live.

v2 features (already shipped): OG share-preview tags + favicon · runtime ?config=URL loading · business-timezone pinning · pluggable analytics track() hook (GA4/Pixel-ready) · showBranding freemium toggle · automatic WCAG AA contrast check.
v3 features (this build — the bridge): Live mode: 4-step flow (service → stylist → datetime → details) with services + stylists fetched from GET /api/public/booking · slots fetched from GET /api/public/booking/slots with real conflict detection · POST to /api/public/booking creates a real Appointment row with customer upsert by phone · graceful fallback to demo mode if backend is unreachable · 409 conflict → banner + auto-refresh slots · 429 rate-limit banner · 400 Zod-validation errors surfaced inline · real booking reference on confirmation screen · email + notes fields added · loading skeletons for API fetches.

Live mode — wiring the widget to a real GlamChain backend

To go live, set business.bookingApiUrl and business.locationId in the config. The widget will fetch services + stylists from the broader GlamChain's public booking API, fetch slots with real conflict detection (already-booked times are crossed out), and POST the booking to create a real Appointment row with customer upsert by phone number. See CORS-PATCH.md for the small middleware change the broader system needs to allow cross-origin calls from the widget. 

// configs/azure-med-spa-live.json
{
  "business": {
    "name": "Azure Med Spa",
    "primaryColor": "#0EA5E9",
    "timezone": "Asia/Dubai",
    "bookingApiUrl": "http://localhost:3001/api/public",
    "locationId": "REPLACE_WITH_REAL_LOCATION_ID",
    "showBranding": true
  }
}

Once the GlamChain dashboard app is running locally on localhost:3001 and the CORS patch is applied, open: booking-widget.html?config=configs/azure-med-spa-live.json — the widget will show 4 steps (service → stylist → datetime → details) and submit a real booking with conflict detection.

Live mode is hidden from this demo page because it requires a running backend. The widget itself handles backend-unreachable gracefully — it falls back to demo mode and shows a yellow banner.

Analytics integration

The widget exposes window.GlamChain.analytics from any host page. Drop this snippet before </body> to forward events to GA4: 

<script>
  window.GlamChain.analytics.setAdapter((event, payload) => {
    gtag('event', event, payload);
  });
</script>

Tracked events (v3 adds booking lifecycle): widget_viewed · booking_started · services_loaded (live) · service_selected · stylist_selected (live) · slots_loaded (live) · date_selected · time_selected · datetime_selected · details_submitted · booking_confirmed · booking_failed · api_unreachable (live) · booking_abandoned (with step number). Every event includes live: true|false so you can compare funnel conversion between demo and live modes.
